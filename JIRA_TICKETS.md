## Тикет 3: Развертывание на тестовую среду

### Заголовок
```
Развернуть SST Site на тестовую среду для тестирования
```

### Тип
**Задача (Task)**

### Приоритет
**High**

### Описание

Необходимо развернуть систему управления терминалами самообслуживания (SST Site) на тестовую среду для проведения тестирования перед production развертыванием.

### Информация о системе

**Название:** SST Site (Self-Service Terminal Management System)

**Назначение:**
Веб-приложение для управления терминалами самообслуживания, которые принимают наличные и пополняют карты или счета. Система обеспечивает полный цикл управления: от поиска локаций для установки терминалов до мониторинга их состояния и выполнения операций (инкассация, ремонт).

**Архитектура:**
- **Frontend:** React SPA (TypeScript, Vite)
- **Backend:** Express.js REST API (TypeScript, Node.js)
- **База данных:** SQLite
- **Порты:** 
  - Backend API: 3000
  - Frontend: 5173 (dev) / статика через backend (production)

### Технические требования

**Серверные требования:**
- Node.js >= 18.x
- npm >= 9.x
- SQLite (встроен в better-sqlite3)
- Минимум 2GB RAM
- Минимум 10GB свободного места на диске

**Переменные окружения:**
```env
PORT=3000
NODE_ENV=production
CLIENT_URL=https://test-sst-site.example.com
DB_PATH=./data/sst-site.db
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your-email@gmail.com
SMTP_PASS=your-app-password
SESSION_SECRET=your-secret-key-here
```

**Сетевые требования:**
- Доступ к SMTP серверу для отправки email
- HTTPS сертификат (рекомендуется)
- Доменное имя для тестовой среды

### Шаги развертывания

1. **Подготовка сервера:**
   - [ ] Установить Node.js >= 18.x
   - [ ] Установить npm >= 9.x
   - [ ] Создать директорию для приложения
   - [ ] Настроить firewall (открыть порты)

2. **Клонирование репозитория:**
   - [ ] Клонировать репозиторий из GitLab
   - [ ] Проверить доступ к репозиторию

3. **Установка зависимостей:**
   ```bash
   npm run install:all
   ```

4. **Настройка окружения:**
   - [ ] Создать файл `.env` с необходимыми переменными
   - [ ] Настроить SMTP для отправки email
   - [ ] Настроить SESSION_SECRET

5. **Инициализация базы данных:**
   ```bash
   npm run db:migrate
   npm run db:add-admin
   ```

6. **Сборка проекта:**
   ```bash
   npm run build
   ```

7. **Настройка процесса:**
   - [ ] Установить PM2 или настроить systemd service
   - [ ] Настроить автозапуск при перезагрузке сервера
   - [ ] Настроить логирование

8. **Настройка веб-сервера (опционально):**
   - [ ] Настроить nginx как reverse proxy
   - [ ] Настроить SSL сертификат
   - [ ] Настроить доменное имя

9. **Запуск приложения:**
   ```bash
   npm start
   # или через PM2
   pm2 start dist/index.js --name sst-site
   ```

10. **Проверка работоспособности:**
    - [ ] Проверить доступность API: `GET /api`
    - [ ] Проверить доступность frontend
    - [ ] Проверить подключение к базе данных
    - [ ] Проверить отправку email (опционально)

### Критерии приемки

- [ ] Приложение успешно развернуто на тестовой среде
- [ ] API доступен и отвечает на запросы
- [ ] Frontend загружается и работает корректно
- [ ] База данных инициализирована и работает
- [ ] Создан администраторский аккаунт
- [ ] Настроен SMTP (или режим разработки активен)
- [ ] Приложение доступно по указанному URL
- [ ] Логирование работает корректно
- [ ] Процесс автоматически перезапускается при сбоях

### Информация для доступа

### Технологический стек

**Backend:**
- Node.js, TypeScript, Express.js
- SQLite (better-sqlite3)
- bcrypt, speakeasy, nodemailer
- helmet, express-rate-limit

**Frontend:**
- React 18, TypeScript
- Vite, React Router
- Axios, i18next

### Основные функции системы

1. Управление терминалами самообслуживания
2. Поиск и управление локациями
3. Система ролей и прав доступа (RBAC)
4. Двухфакторная аутентификация (2FA)
5. Аудит действий пользователей
6. Многоязычность (RU, EN, KY)
7. Отправка email-уведомлений

### Важные замечания

- Проект использует SQLite для базы данных (файл `data/sst-site.db`)
- В production рекомендуется использовать PM2 для управления процессом
- Необходимо настроить резервное копирование базы данных
- Для production рекомендуется использовать HTTPS
- SMTP настройки необходимы для полной функциональности (регистрация, восстановление пароля, заявки на инкассацию)
